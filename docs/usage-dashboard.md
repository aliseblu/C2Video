# 用量看板

重启 Studio 并刷新页面，点击左侧“用量看板”（`/usage`）。可选择最近 7、30、90 天，每 30 秒自动刷新，也可以手动刷新。

## 更新后出现「Unexpected token '<'」怎么办

这通常是新版页面连接到了尚未重启的旧版后端：页面请求 `/api/usage`，旧进程不认识这个接口，却把 Studio 的 HTML 首页返回了。重新构建网页或只刷新浏览器不会重新加载后端代码。

1. 等待正在进行的任务或反馈处理结束，在启动 Studio 的终端按 Ctrl+C 停止旧服务；如果开过多个 Studio，需要确认自己访问的是哪一个。
2. 在项目目录重新运行 `.venv/bin/python -m c2video studio --host 127.0.0.1 --port 8765`。
3. 打开这次启动时实际显示的地址，再进入“用量看板”。端口被占用或不可用时程序会改用其他端口，不要一直沿用旧书签。
4. 在同一地址打开 `/api/usage?days=7` 应看到 JSON 数据，而不是网页。若仍是网页，检查是否打开了旧服务或代理到了错误端口。

修复后，后端对不存在的 `/api` 接口返回 JSON 404，前端也会检查响应类型并提示接口地址和重启方法，不再把 HTML 直接当成 JSON 解析。无需清空任务数据库或重新配置模型密钥。

## 可以看到什么

- 已报告的输入、输出与合计 Token。
- 模型 HTTP 请求次数、失败次数、取消次数、平均请求耗时。
- 每日 Token 趋势、按配置模型和按用途（选题、写稿、记忆整理）拆分。
- 供应商明确返回的美元费用，以及按手动配置价格计算的估算费用。
- 期间新建任务及其当前完成/失败数、当前已启用记忆、期间新增记忆和反馈数。
- 最近 30 次模型请求及来源任务链接；独立 CLI 调用可能没有 Run ID。

接口为 `GET /api/usage?days=7`，只允许 7、30、90。日趋势和时间范围按 UTC 日期统计；最近请求的显示时间使用浏览器本地时区。

## Token 统计口径

统计接入通用模型 Provider 的实际 HTTP 请求，覆盖通过正常配置加载的 CLI、Agent/Studio 的选题和写稿，以及自动记忆整理。一次业务操作可能出现 JSON 格式回退或改稿，因此可以对应多次模型请求；每次请求单独登记。

读取兼容响应中的 `usage.prompt_tokens` / `completion_tokens`，也支持 `input_tokens` / `output_tokens`。若无 `total_tokens`，只有在输入和输出都已知时才相加。缓存输入 Token 如果供应商提供则保留在统计接口中。

没有 usage、不合法的计数、仅有部分计数、网络超时或取消时，缺失部分保留为未知，不按文本长度估算，也不填 0。真正返回的 0 与未知区分开。页面合计是已报告部分，并同时展示用量不完整的请求数，不能认为它一定等于供应商账单总量。

失败响应如果仍带有效 usage，也会计入已报告 Token。接口成功仅表示拿到可用的响应文本，不保证后续结构校验、记忆写入、事实质量或视频制作成功；这些继续由任务与记忆状态表示。

规则编辑、固定 Demo、FFmpeg 和未调用模型的步骤不产生 LLM Token 记录。TTS、知乎接口、图片服务等的计费不在本次统计内。

## 费用不是一律已知

“供应商返回费用”仅接受 `usage.cost_usd` 这种明确美元单位的有效数值。不会把单位未知的通用 `cost` 当作美元，也不会声称已经与供应商账单对账。

若想估算费用，可给 `[llm]` 配置以下两项，数值填写你实际服务和模型的每百万 Token 美元单价：

| TOML 字段 | 环境变量 |
| --- | --- |
| input_usd_per_million | C2VIDEO_LLM_INPUT_USD_PER_MILLION |
| output_usd_per_million | C2VIDEO_LLM_OUTPUT_USD_PER_MILLION |

两项均已配置且输入、输出用量已知时，估算为：

`输入 Token × 输入单价 / 1,000,000 + 输出 Token × 输出单价 / 1,000,000`

估算只用于没有供应商明确返回费用的请求，避免重复计入。它暂不处理缓存折扣、阶梯价、赠送额度、税费或币种转换，不能代替真实账单。价格默认不填写；未填写显示“未提供”，不是免费。

每次请求落库时保存当时计算的估算，之后修改单价不回算历史记录。模型名称记录的是配置值，未推断供应商内部最终使用的模型版本。

## 存储与历史

数据保存在 Studio 同一 SQLite 数据库的 `llm_usage` 表，带创建时间、用途、模型、Run ID、接口状态、用量、耗时和错误类型。数据库迁移新增表与索引，不重写历史任务或记忆。

统计从该功能接入后的请求开始。旧的事件中示例金额、运行器的 Demo 成本或固定评测数字都不会当作实际消耗导入；历史视频不能可靠还原 Token 用量。

用量表不保存提示词、反馈正文、模型回复正文、密钥或完整异常信息。采集失败会记录不含敏感详情的警告，不把一次成功的模型请求变成失败重试。进程强制退出或数据库不可写时，记录仍可能缺失，因此这是本地观察工具，不是强一致计费系统。

## 验证范围

后端使用真实 Provider 包装器和模拟 HTTP 响应验证：成功/失败/取消、格式回退、多次调用、缺失用量、费用口径、时间筛选与任务关联。浏览器验收使用隔离临时数据库和模拟模型响应，验证反馈 → 记忆 → 用量统计的完整交互，以及桌面、手机、深色主题。

这些验证不调用真实付费服务，不代表已证明某供应商当前会返回哪些 usage 字段。实际使用时先配置模型，发送一条不含敏感信息的反馈，检查看板记录与供应商返回是否一致。
