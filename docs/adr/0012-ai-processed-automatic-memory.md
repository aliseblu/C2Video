# 反馈经过 AI 提炼后自动写入记忆

## 背景

旧实现把 preference 反馈原文直接保存为 pending MemoryCandidate，由用户批准。用户要求系统自主写入，但每条新记忆必须先经过 AI 处理。

## 决策

1. 用户反馈是自动提炼触发点，不从第三方资讯或模型自己的输出推断用户偏好。
2. 复用配置的 API 模型，按独立、严格的 Pydantic Schema 返回最多三条长期偏好；仅通过校验、原文依据检查和置信度阈值的结果自动 approved。
3. 无模型、关闭功能、超时、校验失败时保存反馈而不新增记忆；不使用规则模板冒充 AI，不回退到原文复制。
4. 记忆批次采用短事务提交和规范化文本去重，保存出处、模型、版本和处理说明。模型不拥有数据库操作权限。
5. Studio 可以提交反馈、查看提炼依据、停用和重新启用；历史记录保留，未经 AI 处理的历史待审记录需重新提炼。
6. 保持现有任务上下文注入行为。本次不改选题、写稿或媒体制作流程，不承诺偏好已经影响生成结果。

## 取舍

从默认人工批准改成 AI 校验后自动写入，是用户明确要求的行为变更；人工操作保留为事后查看与停用。模型可能误判长期性、语义重复或冲突，有限近期上下文和原文引用检查不能代替完整事实与权限验证。

没有添加向量库、独立队列或新供应商凭证。反馈处理使用有总等待限制的 HTTP 请求，供应商账单和持久重试队列仍不在本次范围。
